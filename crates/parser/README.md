# mqtv-parser

与 mqtv-netdisk 平级的独立 Rust 播放解析包，不依赖 Tauri、应用配置、网盘凭证或播放器。按当前选集解析，不选择或切换线路。

参考 TV ParseJob 的类型分派、单次结果、总超时与取消机制，使用 Rust future 返回终态。

已实现：

- 直链响应识别及静态 HTML 媒体地址提取。
- type 0：网页入口前缀、静态解析，失败后可调用宿主动态解析。
- type 1：JSON 服务，读取 url 或 data.url，并探测媒体响应。
- ParseRequest / Parser / ParseResult，返回 URL、请求头、解析器名称。
- 复用 HTTP 连接池，请求头逐任务设置；带请求头时仍禁止重定向。
- 成功解析结果采用内存 LRU 缓存，最多 128 项、有效期 60 秒；键包含原地址、线路标记、解析配置和请求头。失败及动态宿主结果不缓存，支持显式失效。
- 直链探测响应可单次交接给宿主；响应本身不进入缓存、不序列化。
- 总超时、显式 Cancellation 和任务 future 丢弃时的取消。
- HTTP 状态、响应大小、地址与 TLS 校验；自定义请求头禁止跟随重定向。

ParseHost 为宿主扩展接口，承接动态 WebView 和 type 2/3/4 的 Spider/组合解析。当前桌面应用没有实现这些宿主能力，不会把接口当成已完成的动态嗅探；缺失时明确报错。宿主 future 被丢弃时必须清理关联浏览器任务。

当前 JSON 不自动采用服务响应中的额外请求头；不支持 Android JAR 运行时。没有持久化解析缓存，也不持久化带签名 URL；代理与账号隔离属于应用层职责。

独立验证：cargo test -p mqtv-parser。默认测试使用本机 fixture，不调用真实账号或生产解析服务。

桌面适配层复用同一个 ParseJob；缓存地址准备播放时出现 401/403/404/410 或返回网页，会删除该条缓存并重新解析一次。连接失败、超时或切集取消不重试。媒体代理共用无默认凭证的 HTTP 连接池，首次 HLS 清单复用探测响应，后续清单仍访问上游；二进制媒体保留 Range 获取。缓存只保留当前进程，退出即清空。
