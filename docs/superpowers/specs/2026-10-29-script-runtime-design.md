# JS 与 Python 插件本地执行设计

## 目标与已确定约束

优先补齐订阅中 JS、Python 插件的搜索、详情、选集和播放解析，暂停 CSP 插件移植；其他网盘暂不接入。
用户已选择运行时随应用内置，普通用户不需要安装 Node.js 或 Python。
保留现有 CMS、WoGG、夸克授权、缓存、评分、来源启停和存储契约；不自动启用 /all 中停用的线路。

## 已核实的输入

- 全量接口当前有 85 条 JS、44 条 Python 配置；启用 JS 为 5 条，Python 为 0 条。
- 抽样 drpy2 是 ES module，导入 cheerio.min.js、模板.js、gbk.js；规则依赖同步宿主请求，不能仅用解释器替代整个宿主。
- NyaFun 规则引用 mxpro 模板，说明引擎、模板与规则版本必须匹配。
- 抽样 Python 地址存在返回 HTML 或 HTTP 403 的情况。HTTP 200 和 .py 后缀不能作为可执行脚本的依据。
- 已下载 Acfun.py 样本，确认继承 base.spider.Spider，依赖 requests、BeautifulSoup 和 Crypto（AES/ARC4/padding）；优先以该样本核对 Python 宿主与依赖，不将第三方规则本身随包分发。
- 当前播放列表只接受 HTTP URL；脚本可能返回不透明的选集 ID，需要在用户点选时调用插件 player，而不能提前丢弃。

## 方案比较与推荐

1. QuickJS + 随包 CPython：QuickJS 适合 drpy2 的同步宿主 API，JS 不需要额外 Node；Python 独立进程可终止。推荐此方案。
2. 随包 Node + CPython：适合 Node 原生插件，但旧 drpy2 的同步请求仍需桥接，不能因为装了 Node 就兼容；多一个完整运行时。
3. 首次下载或使用系统解释器：用户已选择随包内置，不采用。

运行时随包已由用户确定；QuickJS 的选型及以下边界是本设计建议，尚待设计确认。

## 执行与协议

- 原生脚本管理层接收来源配置和 search/detail/player 操作，返回经过结构校验的 JSON；前端视图不直接构造执行命令。
- JS：使用 Rust QuickJS 绑定，提供受限 HTTP 请求、模块加载、日志、按来源隔离的键值存储和实际规则需要的编码/加密接口。本期以已取到的 drpy2 模块及匹配模板/规则为首批协议，实现 init/home/homeVod/category/detail/play/search；其他 drpy 版本逐项验证，Cat JS 后续扩展。不宣称兼容 Node 内置模块或 Android API。
- Python：按目标平台随包分发固定版本 CPython，锁定 requests、beautifulsoup4、pycryptodome 等样本依赖；独立 worker 通过 stdin/stdout JSON 通信，日志走 stderr，超时和退出时回收子进程；实现实际样本所需的 base.spider.Spider 宿主。核对 fetch/post、proxyM3u8/proxyMedia/proxyTs 和 localProxy 回调，将代理请求映射到回环媒体服务，不能只实现返回 URL 的 player。
- 插件下载校验协议、状态、大小、内容和模块地址；缓存脚本版本及内容摘要，执行经审核固定的引擎/规则，更新不静默替换已信任代码。自定义脚本使用前须明确授权。
- QuickJS 设置内存、栈和执行时限；HTTP 自身有超时。Python 独立进程不等于沙箱，仍有同用户文件和系统能力；清理子进程环境并使用独立工作目录，不主动注入应用钥匙串和夸克凭证，只执行固定摘要且已审查规则。任意远程 Python 的系统级沙箱不属于本期。
- 保留不透明选集 ID 和 flag，点击播放时调用 player；parse=1、网页嗅探或未支持协议返回明确错误。
- 媒体请求头需要进入受限的本地媒体代理，不能直接丢弃；夸克分享进入现有原生授权流程，其他网盘明确不支持。
- 搜索、详情与播放请求都有请求身份，过期结果不覆盖新选择；切集解析有加载和错误反馈。
- 执行状态按来源与脚本摘要隔离，同来源串行，跨来源不共享 rule/session/Cookie；stdout/stderr 有输出上限，关闭、超时和退出取消对应调用。
- 历史记录保留原始来源、flag 和选集 ID，恢复时重新解析，不依赖短效媒体 URL；兼容旧 CMS 历史。只有运行时、已信任规则及依赖可用的来源才计入可搜索数量。

## 打包与依赖

- 开发和发布均显式解析内置 runtime 路径；发布环境不回退系统 PATH。
- 提供 macOS 与 Windows 对应架构的运行时准备和校验流程，下载固定版本且校验摘要，记录 Python、第三方模块和脚本许可证。
- 构建缺少目标运行时就失败，不输出看似完整但依赖开发机环境的安装包。
- 不改变既定应用标识和签名身份，不安装覆盖已有应用，不发布版本。

## 验收

1. 受控 JS/Python 插件各自完成搜索、详情、不透明选集解析；覆盖异常、超时、输出污染、缺失依赖、取消和进程清理。
2. 前端验证脚本来源识别、结果映射、选集 ID 保留、播放解析与失败展示，保留 CMS/夸克回归检查。
3. 选定真实规则分别验证下载、模块依赖、搜索、详情和 player；无可用上游时明确报告，不以受控样本代替真实兼容。
4. 在实际桌面窗口验证视频起播和进度推进，带请求头的媒体走代理；实际播放与获取 URL 分别记录。
5. 使用项目文档命令运行前端测试/build、Rust 单元测试/check；分别记录已验证平台，macOS 验证不代表 Windows 已验证。
