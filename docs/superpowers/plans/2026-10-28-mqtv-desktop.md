# MQTV 桌面版施工计划

**目标：** 基于 Tauri 2 建设 macOS 和 Windows 桌面应用，从 tvadmin 获取资源，完成影视搜索、详情、选集解析和实际播放，并分阶段支持需要独立运行环境的资源。

**技术栈：** Tauri 2、Rust、React、TypeScript、MUI；播放器方案以实际跨平台验证为准。

**当前决策：** 先做电脑端；Android 不在本计划实施范围内，但共享数据模型和纯解析逻辑不应依赖桌面平台。tvadmin 负责资源管理，不代理影片搜索和播放。

## 当前状态

- 仓库尚无提交，已关联远端。现有文件全部是未提交工作，施工时先检查并保留。
- 资源入口与 TV 客户端一致：`VITE_API_BASE_URL` 加 `/api/resources`（实际域名仅配置在本地环境文件中）。2026-10-28 只读请求返回 HTTP 200、17 条资源：type 1 为 5 条，type 3 为 12 条；实际资源会变化，不应写死数量或推断兼容性。
- 已有 Tauri 模板、React/MUI、TV Logo、初步 CMS 界面和 Rust JSON 请求命令。当前实现是施工中的原型，不是完整可交付版本。
- npm 依赖对齐之前，前端构建、3 项解析测试、Rust `cargo check` 已通过；Tauri 开发启动曾报告前后端依赖次版本不一致，随后调整了 npm 版本，尚未重新验证构建和桌面窗口。
- 目前没有完成真实资源在桌面端的搜索、起播测试；播放直连可能受跨域、请求头和编码限制。没有实现 T4、Spider、JS/Python 环境或媒体代理。
- 当前 HTTP 资源接口是明文传输，网络路径上的修改可能影响源配置；不将其视为可信脚本分发渠道。HTTPS 可用性需另行核实，不假定已部署。
- 当前原型把 feed 和接口地址分开写入 localStorage，不能保证写入中断时二者一致；搜索全部并发；快速切换详情时旧请求可能覆盖新结果。这些都需要在相应阶段修正和验证。
- Rust 原型命令接受渲染层传入的任意 HTTP(S) URL 并自动跟随重定向，尚未验证私网策略和每次跳转的限制；调用权限与地址策略必须在交付前收紧。

## 参考与边界

- tvadmin：`GET /api/resources`、`GET /api/resources/check?version=...`；返回顶层 `version`、`count`、`sites`，以及可能存在的全局字段。
- 资源同步遵循 tvadmin 契约：校验完整结果并保存成功后再更新版本；失败保留旧配置；空列表是合法配置；遵守 `searchable`。保留原始 `ext`、`jar`、`header`、`playUrl` 等字段。
- LibreTV 的 `src/lib/cms-parser.ts`、`src/lib/tvbox-parser.ts`、`src/lib/spider-bridge.ts`、播放器及代理实现是参考来源。复用代码前检查 AGPL-3.0-or-later 许可、版权声明与分发义务。
- type 1、type 3、type 4 只是识别入口，不代表协议或运行能力已经兼容。Android JAR/DEX、远程脚本、网页嗅探和依赖特殊宿主的资源不能默认执行。
- 不改 tvadmin 和 LibreTV 的持久数据、生产配置或远端部署；不提交、推送或发布，除非另有明确要求。

## 模块职责

以下是施工目标，具体文件可以根据实现调整：

| 模块 | 职责 |
| --- | --- |
| 资源同步 | 读取、验证、缓存 tvadmin 配置和版本；区分源类型及不支持原因 |
| CMS/T4 适配 | 搜索、详情、线路与选集的协议转换；保留源与播放参数 |
| 网络层 | 管理超时、并发、响应大小、重定向和允许访问的地址；避免渲染层获得任意网络或进程权限 |
| 播放和媒体代理 | 控制播放器，按需要处理请求头、HLS 播放列表、分片、密钥和 Range |
| 解析引擎 | 按需管理可信 JS/Python 运行环境；明确进程、协议、平台及版本边界 |
| 界面和状态 | MUI 搜索、资源状态、详情、选集、播放器、错误和缓存状态 |

建议从现有 `src/media.ts` 和 `src/App.tsx` 中按上述职责逐步拆出资源、搜索和播放器模块；Rust 的 `src-tauri/src/lib.rs` 只保留命令注册，网络和媒体处理分别放入独立模块。拆分服务于实际功能和测试，不预先搭建通用插件框架。

## 交付顺序

1. **桌面最小闭环：** 完成第 1～4 阶段，以真实 CMS 起播为验收；type 3 等不支持项明确展示。
2. **T4：** 完成第 5 阶段，单独验证后声明支持；当前线上样本未观察到 type 4，需寻找可验证样本。
3. **脚本资源：** 完成第 6 阶段，按具体引擎和规则逐项支持，不承诺所有 TVBox 脚本兼容。
4. **发行：** 完成第 7 阶段，分别验证 macOS 与 Windows 安装包。

## 施工步骤

### 1. 整理和验证基础工程

- [ ] 检查已有未提交文件与版本，整理初始原型，不覆盖无关改动；将原型中与最终方案不一致的部分记录并调整。
- [ ] 对齐 Tauri npm / Rust 包版本，确认 macOS 可执行 `npm run tauri dev` 并打开桌面窗口。Windows 使用相应构建环境单独验证。
- [ ] 固定或约束依赖版本，补充项目启动、测试和构建命令；保留 TV Logo。
- [ ] 用真实桌面窗口确认应用启动、退出、窗口尺寸及错误展示，记录运行平台和结果。

### 2. 资源同步与缓存

- [ ] 默认使用 TV 项目的资源接口，支持修改地址；将来源地址、版本和完整 feed 作为同一份缓存提交，地址变更失败不丢失已有配置或错误地标记新版本。
- [ ] 检查并保存完整 feed，正确处理版本变化、空列表、格式错误、超时及重启后的缓存恢复；不因不支持的类型丢弃其原始字段。
- [ ] 限制网络请求的协议、重定向和大小，明确本地/私网访问策略；不要暴露通用任意 URL 调用给不可信页面或插件。
- [ ] 用临时服务测试首次同步、无变化、更新、空列表、异常数据、保存失败及断网保留缓存；重启后检查地址、版本、内容来自同一次成功同步，再对真实 tvadmin 只读验证数量与版本。

### 3. CMS 搜索、详情和线路

- [ ] 从实际 feed 中识别可用 CMS，使用可控并发和超时搜索；遵守搜索开关，区分无结果、部分失败和全部失败；使用请求标识或取消机制避免旧搜索和详情覆盖新选择。
- [ ] 复用或对照 LibreTV 解析：保留 URL 参数、关键词编码、结果来源、详情及多线路/选集；避免将网页中转地址当作已验证的媒体。
- [ ] 增加协议测试：空列表、异常响应、特殊字符、多个线路、含查询参数的地址、部分源超时，以及连续切换影片时的乱序响应。
- [ ] 用真实 CMS 来源完成搜索到详情、选集的测试，记录来源、失败原因和验证时间；不把接口返回当作起播证明。

### 4. 播放与代理

- [ ] 确定 macOS WKWebView、Windows WebView2 下的播放器策略；实现选集切换、暂停、进度、全屏、加载与失败状态。
- [ ] 根据真实资源实现必要的本地媒体代理：支持请求头、HLS 主/子播放列表、相对 URL、分片和密钥，以及媒体 Range；只监听回环地址，限制可访问范围并处理生命周期。
- [ ] 使用本地受控媒体服务覆盖重定向、请求头、HLS、Range 和错误；分别在 macOS、Windows 实测实际视频画面、进度推进、切集和退出清理。
- [ ] 标记不支持的加密、编码、网页嗅探和特殊解析方式；不将获取 URL 当成播放成功。

### 5. HTTP T4

- [ ] 按 LibreTV 桥接协议实现搜索、详情和基于来源及选集的解析，保留 flag 和必要上下文；对 `parse=1`、请求头及网页结果明确处理或报不支持。
- [ ] 用可控服务测试搜索、详情、播放解析、错误和超时；用至少一个真实 T4 源跑通到实际起播。

### 6. JS 和 Python 解析环境

- [ ] 先统计当前实际 type 3 资源的格式及依赖，选择具体 JS 和 Python 样本；记录需要的宿主 API、版本、许可证和平台支持，不按后缀宣称兼容。
- [ ] 优先评估 LibreTV 固定版本 drpyS 与 Node 22：在独立进程中完成启动、健康检查、停止和失败恢复，验证打包后在 macOS、Windows 的实际运行。
- [ ] 根据选定 Python 规则决定运行时及依赖，建立明确的搜索、详情、解析协议和超时限制；分别验证两个桌面平台。
- [ ] 先运行受控、经过检查的规则；明确远程脚本获取、完整性、权限、网络/文件访问和用户可见错误。独立进程不等同于安全沙箱，不默认执行 tvadmin 下发的任意脚本。
- [ ] 每种已声称支持的类型至少有一个真实样本走完搜索、详情、解析和实际播放；无法支持的条目在界面显示原因。

### 7. 打包与验收

- [ ] 分别生成目标架构的 macOS 和 Windows 包，验证干净环境下安装、启动、资源同步、搜索、播放、退出和数据保留。
- [ ] 测量安装包、安装后体积、空闲内存、解析进程和播放表现；分别记录 Node/Python 是否随包或按需安装。
- [ ] 核对依赖和引用代码许可证、分发方式、更新及签名要求；签名、公证、发布须按实际授权执行。
- [ ] 最终记录测试平台、资源样本、成功与失败原因，以及 Android 尚未实施的边界。

## 每阶段检查命令

- [ ] 运行 `npx vitest run`、`npm run build` 和 `cargo check --manifest-path src-tauri/Cargo.toml`，记录结果；增加测试后使用项目脚本固化命令。
- [ ] 对影响桌面链路的任务运行 `npm run tauri dev`，在实际窗口验证并正常退出；构建或模拟接口结果不能代替真实播放验证。

## 完成标准

首个可用桌面版本至少满足：真实 tvadmin 配置同步及断网缓存；一个真实 CMS 资源搜索、详情、选集到实际播放；桌面窗口可正常退出；不支持的资源明确提示。T4、JS/Python 和 Windows 均需各自完成对应阶段验证，才可宣称支持。
