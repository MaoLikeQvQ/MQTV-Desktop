# 开发文档

[返回应用说明](../README.md) · [文档目录](README.md)

本文面向开发与维护人员，记录架构、缓存、授权、测试及打包约定。应用功能、资源兼容与免责声明见根目录 README。

## 本地开发

技术栈：React + MUI + Tauri 2。开发前需准备 Node.js/npm、Rust 工具链及对应平台的 [Tauri 开发依赖](https://v2.tauri.app/start/prerequisites/)。

```sh
npm install
pnpm dev
```

`pnpm dev` 启动 Tauri 桌面应用，并自动启动 Vite 前端服务；只调试网页前端时使用 `pnpm dev:web`。启动命令需要本机已安装 pnpm。

默认资源接口为 `http://tvadmin.maolike.cn/api/resources`。资源订阅、授权和更新请求使用该后台域名；发现页列表及豆瓣封面直接请求豆瓣；旧本地默认地址自动迁移，用户自定义订阅保留。应用打包名称为“晴雨影视”。

## 统一搜索与夸克

默认订阅和自定义订阅均允许当前已适配的 JSON CMS（type=1）与配置有效的 WoGG 线路参与搜索，仍尊重 searchable=0，不执行其他 Android 插件或脚本。只使用订阅实际返回的线路，不自动改用全量资源接口或启用后台停用线路。

- 支持带 `ext.siteUrl` / `ext.site` 的 HTTPS WoGG 来源。
- `csp_WoGGGuard` 没有显式站点配置时，桌面适配使用 `https://www.wogg.net/`。
- 不运行 Android JAR；其他插件需要单独适配。
- 搜索结果保留来源，点击影片后内部遍历夸克目录和分页，直接展示可播放选集，无需手动浏览文件夹。
- 首次访问文件时从同一后台 `/api/authorizations/quark` 领取账号，保存到 macOS Keychain / Windows Credential Manager。Cookie 不返回 React、不保存在 localStorage。
- 本地授权持续复用；仅明确的认证失效触发重新分配，网络超时、限流和影片失败保留授权。设置可检查授权。
- 用户点击“播放”后，内部将视频保存到账号的 `MQTV` 目录，复用已保存文件；不会自动删除网盘内容。
- 使用夸克视频播放接口，播放清单、分片和密钥经随机路径的回环 HTTP 服务转发；Cookie 只发往夸克域名。

## 打包签名要求

每次打包都必须使用同一套签名。首次确定签名后，后续版本、不同架构的安装包及重新打包的产物均须沿用对应平台的既定签名身份，不得临时生成或切换签名。

- macOS 沿用同一开发者团队及签名身份；Windows 沿用同一发布者的代码签名证书。
- 应用标识保持为 `com.maolike.mqtv.desktop`，不得因改名或重新打包而变更。
- 打包前核对签名配置，打包后核对产物的签名身份与上一版一致；签名缺失或不一致时，不得作为正式安装包发布。
- 证书、私钥和密码通过安全存储或构建环境提供，不写入仓库。证书续期或签名迁移须单独确认，并验证旧版覆盖安装、更新及系统凭证访问。

本节规定后续打包要求，不代表已有安装包已完成固定身份签名；实际使用的签名身份以产物核验结果为准。


## 界面

推荐首页及电影、电视剧、动漫、综艺分类按完整接口地址分别持久缓存。每次应用启动时，以各列表上次成功获取时间判断：1 小时内（含整 1 小时）直接复用，超过 1 小时则在本次首次进入对应页面时更新一次。同一次运行中不会因为超过 1 小时、切换页面或跨天再次自动请求；尚未缓存的分类首次访问时正常加载。更新时先显示旧缓存，失败保留旧内容和时间，切换页面不自动重试；用户点击“重试”或下次启动后再尝试。相同内容的并发请求合并为一次，不缓存失败响应。

推荐、动漫和搜索结果海报按原始图片 URL 存入本机 IndexedDB，重启后仍优先使用已下载图片；数据刷新但图片 URL 未变时也不重复下载。内存保留最近 120 张，持久图片缓存上限 128MB，超出后按最近使用时间淘汰最旧图片；图片不跟随列表的 1 小时门槛过期。只有未缓存、被淘汰或缓存不可用时才重新下载。存储写入失败时仍能正常显示本次下载的图片。

搜索结果采用横向海报卡片：左侧海报、右侧名称及真实分类/年份/更新状态、底部播放入口。多个夸克资源依次显示“线路 1、线路 2、线路 3”。选集使用原始文件名，目录路径放在悬停提示中。播放时右上角显示该文件实际字节数换算的大小，悬停选集也可预先查看大小。

选集卡片在文件名上方显示 `300MB`、`5GB` 等文件大小。短文件名占一格并居中，长文件名最多占两格；超过两格宽度的名称自动横向循环滚动，悬停暂停。系统开启减少动态效果时改为手动横向滚动。

播放器使用独立的自定义控制层，顶部显示影片名、当前选集及文件大小；底部提供上一集、播放/暂停、下一集、进度拖动、缓冲进度、前后跳转 10 秒、音量、倍速、全屏及环境支持时的画中画。普通线路按当前播放集所属线路切集，夸克选集复用原有播放解析流程，准备期间禁用切集并展示状态，失败信息在全屏内可见；首尾集禁用越界按钮，不自动连播。播放中控件自动隐藏，暂停、加载或错误时保持显示，移动鼠标或键盘聚焦可唤出。全屏保留整套控制层；环境不支持容器全屏时使用窗口内铺满模式，Esc 可退出。播放器聚焦时支持空格播放/暂停、左右方向键跳转 10 秒、M 静音、F 全屏、[ 上一集、] 下一集。

设置页顶部提供“基础设置”“资源服务”和“授权管理”标签，不显示搜索框。授权管理按网盘展示，目前接入夸克；点击夸克条目生成二维码，仅弹窗打开时轮询。扫码并独立验证成功后保存到系统安全存储，作为本机当前授权，替换前保留原授权。扫码凭证不上传资源服务，不返回 React。关闭弹窗停止轮询；本地扫码授权失效时需重新扫码，不自动切换为服务端账号。

资源服务可选择默认或自定义，单独保留自定义地址。默认资源按地址持久缓存，成功获取满 7 天后，在应用启动、恢复可见或运行中的定期检查时更新；7 天内切回默认或重启均复用缓存。更新失败保留原缓存和更新时间。自定义资源在保存或启动时请求。当前默认地址为 http://tvadmin.maolike.cn/api/resources。桌面面板、按钮、输入框和弹窗统一采用 4px 圆角。

资源设置使用“影片资源地址 + 默认/自定义下拉菜单”。自定义模式维护本机订阅列表，可新增、编辑、删除、过滤和独立启停。新增或编辑时先请求并解析，成功后保存且启用；解析失败保留原配置，不保存本次输入。已保存订阅在启动或检查时校验，失败项显示错误并停用。多个启用且校验成功的订阅合并参与搜索，用订阅 ID 隔离来源 key。检查全部资源重试错误项，保留手动关闭的正常项。列表兼容迁移原自定义地址。默认资源保持独立的 7 天缓存策略。

## 搜索归并与线路评分

搜索参照 TV 的 TitleGroups：统一 NFKC 全半角、大小写和 Unicode 空白，移除末尾波浪分隔符。同名影片显示一张卡片，同一来源同一 ID 去重，不同来源或不同 ID 的入口保留在详情“影片来源”中。季数、语言、电影版等后缀保留，不做模糊合并。搜索页仅展示“全部”和归并后的影片总数，不再显示大标题、说明或来源筛选。

仅默认资源服务提供的自有线路参与评分；自定义资源不累计、不展示评分，也不使用历史评分排序，搜索归并和播放照常。本机搜索评分按成功率 60%、标题相关性 30%、响应速度 10% 计算（各项百分制），速度为 1 / (1 + 平均耗时 / 3000)。相关性移植 TV SearchRelevance v1：完全匹配优先，其次包含、词组、拆字；按原始结果排名加权。空结果算请求成功，相关性未知，未知项按已有权重折算。失败请求计入成功率和平均耗时，不计为零相关性。

自有线路按显示评分从高到低排序，未评分线路排在已评分线路之后；每次搜索读取系统可用处理器并行度，并发数取其 75% 向下取整（最少 1 路、最多 16 路，且不超过来源数）；系统读取失败时提示并使用 WebView 报告的逻辑处理器数。此策略依据处理器能力，不检测实时 CPU 负载或内存压力，不因低分关闭来源。自定义资源维持配置顺序。这一权重顺序仅决定并发请求的发起顺序；搜索结果和同名入口参照 TV，按实际返回顺序追加显示。注意 TV 当前本地 SourceScore 仍为 65/30/5，桌面采用 tvadmin 质量统计的 60/30/10，未直接复制旧权重。

搜索时每个来源完成就立即更新结果，无需等待全部来源；有结果后即可打开影片，其他来源继续搜索。搜索等待区显示居中的猫爪加载标识，不显示骨架屏、来源数量或来源完成进度；部分失败显示简短提示。顶部栏下沿使用 2px 导航式加载条，搜索、资源同步、详情请求及推荐/分类列表请求共用，完成后收满淡出；该细线表示加载活动，不代表实际完成百分比。快速请求和有效缓存命中不闪烁进度条。后续结果按返回顺序追加归并，不重排已有卡片。

评分在本机持久保存，按资源服务地址、来源 key、api、ext 的 SHA-256 摘要隔离，最多保留最近 512 个来源；仅保存数字统计，不保存搜索词或标题。详情中的影片来源显示实测分及样本数。评分衡量搜索表现，不代表播放成功率；不上传服务端，不操作后端资源开关。默认订阅已恢复已适配的多来源搜索；来源连通性、桌面交互及实际播放分别验证。

自定义资源支持标准资源接口与 TVBox `sites` 配置，来源搜索仅支持已适配的 WoGG 或 `type: 1` HTTP CMS；不执行 Android JAR 或 JavaScript 插件。界面分别显示配置来源总数与支持搜索数，配置解析成功不代表来源已连通或可播放。

授权管理增加“使用授权码”入口。桌面原生层向 tvadmin /api/authorizations/quark 提交 authorizationCode 领取内测夸克授权，成功后保存到系统安全存储；错误或网络失败保留原授权。授权码不写 localStorage，不作为 URL 参数，凭证不返回 React。正常播放持续复用本地授权，仅明确认证失效才携带已保存的授权码重新领取。扫码授权仍独立可用。

## 桌面版本更新

设置 → 基础设置 → 版本更新，点击右侧图标手动检查。客户端使用默认资源服务同源的 tvadmin /api/update，发送实际平台（macos/windows）、架构、系统版本、应用标识和构建号。发现兼容的新版后展示版本说明，点击“下载新版”通过系统浏览器下载安装包，再手动安装；暂无兼容版本和请求失败分别提示。

发布时同步提升 Tauri 应用版本和 src-tauri/src/commands/app.rs 的 APP_BUILD（当前为 1）；tvadmin 上传对应安装包时，应用标识填写 com.maolike.mqtv.desktop、客户端类型为 desktop，构建号必须大于已安装版本，选择对应平台、架构与最低系统版本，并发布后才会被检查接口返回。更新服务、默认资源订阅与图片代理统一使用根目录环境变量 VITE_API_BASE_URL，默认值见 .env。

## 动漫频道

动漫页分为“今日推荐、日本动漫、中国动漫”三个内容区，使用四列横版封面卡片，随窗口宽度调整列数。点击影片沿用统一搜索流程。今日推荐按北京时间日期从日漫、国漫列表混合轮换，点击“换一换”只切换本地推荐，不重新请求接口；图标旋转期间和地区列表加载期间禁止重复触发。

日本动漫使用豆瓣日本动画列表，中国动漫使用豆瓣“中国大陆＋动画”筛选（包含动画电影和剧集）。每日更新与 Bangumi 放送请求已移除。

两份地区数据按日本、中国的页面顺序发起并发请求，哪个先返回就先展示对应区域，遵循上述“启动时检查 1 小时、同次运行复用”的缓存规则；更新失败时保留旧内容并提示，单一区域失败不阻塞其他区域。动漫封面经原生 fetch_cover 直接获取，直连限于 HTTPS 豆瓣图片域名和 lain.bgm.tv；其他发现频道同样直连豆瓣封面。

## 前端目录约定

参考同级项目 `maolike-desktop/frontend`，当前项目统一使用 `frontend/` 作为前端源码根目录，`@/` 指向该目录。Vite 的 HTML 入口、TypeScript 路径和构建配置已同步；启动及构建命令保持不变。

```text
frontend/
├── api/             # 接口路径、参数、返回类型与请求函数
├── config/          # 环境变量与公共服务域名
├── services/        # 请求与业务规则组合、缓存加载及图片持久化
├── platform/        # 桌面环境判断、系统信息及外部链接
├── utils/           # 统一请求工具、URL 校验与参数编码
├── assets/images/   # 本地 SVG、PNG 等静态资源，交由 Vite 处理路径
├── domain/          # 媒体解析、搜索评分、动漫映射、资源/列表缓存及版本校验
├── router/          # 频道菜单、页面类型、设置标签及内存导航
├── styles/          # 全局、发现、搜索、播放器、设置和动漫样式
├── theme/           # MUI 主题
├── views/
│   ├── app/         # 应用布局与搜索、播放、资源状态协调
│   ├── discovery/   # 推荐、分类和动漫页面及推荐卡片
│   ├── player/      # 播放器、夸克选集和集数按钮
│   ├── search/      # 搜索结果卡片
│   ├── settings/    # 基础、资源和授权设置
│   └── shared/      # 缓存图片、顶部加载条等共享组件
├── main.tsx         # 组合主题、全局样式并挂载应用
└── vite-env.d.ts
```

页面调用 `api/` 请求函数或 `services/` 业务流程，桌面能力通过 `platform/` 使用，不直接调用 Tauri `invoke`；纯解析和规则放在 `domain/`，对应测试集中在 `frontend/tests/`，内部按业务目录分类。资源链接通过 import 引入，避免依赖旧 `public/` 根路径。样式从 `styles/index.css` 按原有顺序统一加载，保持层叠效果。

当前仍使用内存页面切换，搜索结果在切页后保留；本次整理没有增加路由依赖或改变 URL。localStorage 键、IndexedDB 名称与缓存策略保持兼容。Rust 代码保留在 `src-tauri/`，参考项目只读使用。


### Tauri 职责划分

```text
src-tauri/src/
├── main.rs                 # 桌面程序入口
├── lib.rs                  # 插件装配、原生命令注册、启动应用
├── commands/
│   ├── app.rs              # 系统/版本信息、设备搜索并发能力、APP_BUILD
│   ├── http.rs             # 通用 JSON 请求与响应大小限制
│   └── images.rs           # 封面/图片下载、来源校验、格式与大小限制
└── features/quark/
    ├── mod.rs              # 夸克模块边界
    ├── credentials.rs      # 钥匙串存储、序列化配置、共享授权锁
    ├── client.rs           # 夸克请求、Cookie 更新、后台地址校验
    ├── authorization.rs    # 授权码、授权复用、失效刷新、账号验证
    ├── login.rs            # 扫码会话的创建、轮询、取消
    ├── search.rs           # 线路搜索、结果解析、详情分享链接提取
    ├── files.rs            # 分享目录、分页和选集遍历
    ├── playback.rs         # 转存复用、播放准备、获取播放地址
    └── proxy.rs            # 本地媒体代理、Range 转发、HLS 地址改写
```

命令直接定义在负责该能力的模块内，`lib.rs` 统一注册，避免增加只做转发的包装层。通用能力放入 `commands/`，夸克相关能力放入 `features/quark/`；Rust 测试源码集中放在 `src-tauri/src/tests/`。前端命令名称、参数及返回结构、钥匙串服务名与配置字段保持兼容。涉及真实网络、账号或转存的测试继续默认忽略。


### 环境变量与统一请求

根目录 `.env` 保存可公开的默认服务域名，`.env.example` 提供配置示例；本机覆盖写入 `.env.local`（已由 `.gitignore` 忽略）。这些值会打进安装包，**不要放 Cookie、授权码、Token 或其他凭证**。

```dotenv
VITE_API_BASE_URL=http://tvadmin.maolike.cn
VITE_DOUBAN_BASE_URL=https://movie.douban.com
VITE_BANGUMI_BASE_URL=https://api.bgm.tv
```

- `VITE_API_BASE_URL`：项目后台，供默认资源订阅、发现页、版本检查、封面代理、夸克默认授权后台共用。
- `VITE_DOUBAN_BASE_URL`：动漫日本/中国分类数据的请求域名。
- `VITE_BANGUMI_BASE_URL`：动漫放送日历的请求域名。

配置值应是完整的 HTTP(S) origin，可带端口，不带接口路径、参数、片段或凭证；请使用字面量域名，不做变量插值。接口路径由业务 API 模块管理。用户自行添加的资源订阅和 CMS 地址仍使用用户配置；夸克官方登录、网盘和媒体上游地址属于协议地址，保留在对应原生模块内。

Vite 与 Rust 构建读取相同的根目录文件，优先级从低到高为 `.env`、`.env.local`、`.env.[mode]`、`.env.[mode].local`，已设置的进程环境变量优先。默认开发/调试使用 `development`，构建/发布使用 `production`。如需自定义模式，通过 `MQTV_ENV_MODE` 同时指定前端和 Rust 的模式：

```sh
MQTV_ENV_MODE=staging npm run tauri dev
MQTV_ENV_MODE=staging npm run tauri build
```

修改配置后，重启开发命令；已打包应用需要重新构建才生效。Rust 构建通过 `dotenvy` 解析配置，只将 `VITE_API_BASE_URL` 编译到原生侧，供 `src-tauri/src/config.rs` 生成后台接口地址。

前端请求调用链：`views → services（有业务组合时）→ api → utils/request.ts → Tauri`。`utils/url.ts` 统一校验 URL、保留已有参数并编码新参数；`utils/request.ts` 统一 JSON 请求与错误对象，图片请求在 `api/images.ts`，超时、HTTP 状态、JSON 解码和响应大小限制继续由 Rust 执行。请求失败不会自动重试，避免重复授权或覆盖现有缓存重试策略。

| 模块 | 职责 |
| --- | --- |
| `api/discovery.ts` | 推荐、分类、动漫接口地址、参数与原始响应请求 |
| `api/resources.ts` | 资源订阅原始 JSON 请求 |
| `api/media.ts` | CMS 搜索、详情请求，保留来源地址上的查询参数 |
| `api/update.ts` | 更新接口参数及原始响应请求 |
| `api/quark.ts` | 夸克原生请求及参数转换 |
| `api/images.ts` | 图片原始字节请求与封面下载命令选择 |
| `services/` | 动漫响应解析、更新契约校验、订阅缓存与聚合、图片持久缓存 |
| `config/services.ts` | 环境变量读取、服务域名与默认资源地址 |
| `platform/desktop.ts` | 桌面判断、系统信息和打开系统浏览器 |

页面不再拼接 HTTP 接口或调用通用 JSON 传输。默认资源模式随环境配置切换；旧默认地址会迁移到当前配置，默认资源缓存按完整地址隔离，不用上一环境的聚合资源数据作为回退。发现页一小时启动缓存与图片持久缓存规则保持不变。

生产 JavaScript/TypeScript 的具名函数使用中文 JSDoc，覆盖请求函数、业务规则、缓存方法、内部工具、组件、Hook 和具名事件处理函数。注释说明用途，对不直观的参数、返回值、异常、副作用及缓存/授权约束补充必要说明；匿名数组回调、JSX 内联处理和测试回调不重复添加模板注释。修改函数行为时同步更新注释。

### 豆瓣发现数据直连

推荐、电影、电视剧、综艺及动漫列表通过 `movie.douban.com` 的 `/j/search_subjects`、`/j/new_search_subjects` 加载，不依赖后台的榜单或豆瓣转发路由。推荐页默认一周口碑榜通过原生 `douban_weekly` 读取豆瓣 `/chart`，仅解析口碑榜区域并保留原始排名；榜单先显示，再按排名并发查询 `/j/subject_suggest`，以影片 ID 精确匹配并逐张补充封面。电影页继续使用热门列表；海外剧和海外综艺分别读取美国、英国、日本、韩国并交替合并去重，完整保留每页各地区的条目以避免分页遗漏。各地区按展示顺序发起并发请求，每份结果返回立即显示，不等待其他地区；地区失败不影响其他请求，最后明确提示失败，不缓存不完整的聚合结果。

API 层返回豆瓣原始响应，服务层使用通用豆瓣解析器转换成发现条目；保留原有一小时启动缓存和手动重试。豆瓣封面直连图片域名并使用原生来源请求头，继续写入已有图片缓存。资源订阅、授权和版本更新仍使用 tvadmin。

### 发现列表滚动分页

电影、电视剧、综艺、推荐页的非周榜分类以及动漫地区列表支持接近底部时加载下一页，并保留“加载更多”和错误重试按钮。一周口碑榜固定展示榜单十部，不分页；今日推荐仍从已缓存的首屏动漫条目中轮换。

豆瓣 search_subjects 按每页 30 条递增 page_start（日本动漫为 24），new_search_subjects 按每页 20 条递增 start。各地区分页请求仍按顺序并发发起并逐份展示；结果按 ID 去重追加。空页或只有重复内容时停止，失败保留已有内容并重试原页；切换分类或离开页面后忽略旧响应。后续页只存当前视图，首屏沿用原有一小时缓存。

### 夸克分享错误诊断

分享访问令牌请求可能因上游内容删除而返回 HTTP 404。41004 表示文件不存在，41006 表示分享不存在；客户端将其显示为分享错误并建议切换影片来源，保留现有授权，不触发重新领取。明确的 HTTP/业务状态 401 仍按授权失效处理。错误信息不回显响应正文中的未知敏感字段。

选集区的“重新解析”会重新请求来源详情、读取最新分享链接，再解析文件，不只是重试先前的旧分享。历史恢复时不会把旧进度自动套到另一条分享上。

## JS / Python 本地插件

桌面端新增 QuickJS 宿主与随包 CPython worker，订阅中的 `type=3` HTTP `.js` / `.py` 来源可进入脚本检查流程。`csp_` Android JAR 不由这两个运行时执行。当前 JS 协议为 `init/search/detail/play/home/homeVod/category`，覆盖 drpy2 模块式入口；Python 为 `base.spider.Spider` 的标准方法。Node 内置模块、浏览器嗅探以及任意第三方宿主 API 不自动兼容。

在“设置 → 资源服务 → JS / Python 插件”检查脚本，下载入口、JS 静态依赖与规则配置后显示 SHA-256 摘要；检查不执行代码。只有用户明确选择“信任并启用此内容”后才参与搜索。运行的是该固定快照，重新检查发现内容变化会撤销原授权。后台 `searchable=0` 和原有订阅启停仍有效，不自动读取全量接口或启用停用来源。Python 插件具有本机用户的系统能力，独立进程不是安全沙箱，仅应授权已审查来源。

JS 静态依赖由 QuickJS 只编译模式识别，包含 `import` 和 `export … from`，不会把 cheerio 等压缩模块中字符串、注释、正则或模板文本中的关键词当作依赖。检查期间使用空模块占位，不执行源码，不提供网络宿主；实际依赖继续经原有下载、大小和 HTTP(S) 地址校验后进入摘要。动态 `import()` 不会在检查时执行或自动下载，运行时只能加载授权快照中已有的模块；Node 内置模块和裸包名仍不支持。

脚本缓存与原始配置、来源标识及摘要绑定，成功调用才保存不超过 1 MiB 的来源状态。JS 有 96 MiB 内存及 30 秒执行上限，宿主请求有 15 秒和 8 MiB 响应上限。Python 调用有原生进程时限、输出限制与错误隔离；不继承应用配置或夸克凭证，不回退系统解释器。第三方脚本绕过宿主自行调用网络库仍受进程总时限约束。

脚本详情保留不透明选集 ID，点击播放再调用插件解析；历史记录保留原始 ID 与线路，恢复时重新解析。带请求头的媒体由随机路径的回环代理提供，处理 HLS 相对清单、分片、密钥和 Range。需要 `parse=1`/`jx=1` 网页嗅探的结果明确报不支持。夸克分享交现有夸克流程；其他网盘不在本次范围。

## Rust 多包结构与网盘边界

根目录 Cargo workspace 包含 Tauri 应用与 `crates/netdisk`（`mqtv-netdisk`）。锁文件与 release profile 统一放在根目录；`.cargo/config.toml` 保留构建产物位置 `src-tauri/target`，原有 Tauri 打包和内置 Python 路径不变。

网盘包的 `quark` 模块负责 HTTP/Cookie 更新、扫码会话、分享目录、选集、转存、播放与媒体代理。它不依赖 Tauri、钥匙串或 tvadmin。应用通过 `CredentialStore` 提供原生凭证快照、保存 Cookie/转存记录、安装扫码授权；保留原钥匙串服务名与字段格式。应用命令负责持有包提供的共享授权锁，准备/刷新 tvadmin 授权，转发到包接口。播放失效仍要求用户重新点击，不自动重复转存。应用退出同时关闭脚本与夸克媒体代理。

WoGG 搜索与 HTML 详情提取属于来源适配，仍留在应用中。未来新增网盘可在包内增加同级 provider 模块，按实际共性提取类型；目前不创建其他网盘占位实现。前端 API、localStorage 和播放历史契约不变。
